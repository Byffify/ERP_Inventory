# Critique: sale/cart and product editing

Current authority: eBay reference and the approved separation of Inventory data administration from Stock management. Target: src/App.tsx with SaleSelection, InventoryHome and CatalogForm. User wants simple add-to-cart/single summary and fewer edit steps. This report recommends changes; it does not claim that the cart/edit simplification has been implemented.

## Design specificity and overall impression

The Thai stock terms, model/variant grouping, explicit units, bill consequences and traditional document make this product-specific. Visual identity is coherent enough. The larger weakness is the interaction architecture: two interfaces select the same goods, quantity exists in a staging dialog and the order, and editing inherits a creation wizard. Simplify tasks before another visual redesign.

## Priority issues

### [P1] Two ways to add the same product

src/App.tsx:671 opens the separate picker; :832 opens a second in-editor picker with separate search/filters. The empty editor also repeats selection guidance. Users must infer whether these are different jobs.

Fix: sale opens directly to one searchable product list with add-to-cart actions. Remove the editor's duplicate picker. One cart count/total and one ดูสรุป action. Suggested command: $impeccable distill.

### [P1] An intermediate basket precedes the real basket

src/InventoryHome.tsx:23 opens SaleSelection. src/SaleSelection.tsx keeps staging quantities and requires เพิ่มในบิล; src/App.tsx:682 renders another quantity editor. Even one plain product requires opening and applying a dialog.

Fix: click a simple available SKU to add one; repeat clicks increment with visible feedback. Multi-option products expand inline so clicking an explicit color/size adds it. Quantities/removal live in the cart summary using one persistent state. Suggested command: $impeccable shape.

### [P1] Routine edits inherit a creation wizard

src/CatalogForm.tsx:37–39 displays three steps on edit. Name/main-photo edits have no direct step-1 save. :56 offers both direct save and review on step 2, making review seem either optional or required.

Fix: one edit page for model details and compact existing variant rows, one primary บันทึกการแก้ไข and cancel. Optional add-color/size disclosure; locked identity becomes read-only text. Inline validation and preserved unsaved-work guard. Stock editing remains exclusively Stock management. Suggested command: $impeccable distill.

### [P2] Mobile summary follows repeated controls

The current-theme 320px order capture places optional document fields and duplicate product lookup before total/confirmation. One item already extends the page enough to hide the final action below the fold.

Fix: product list gets count/total/ดูสรุป cart bar; one cart screen contains quantities, optional document details, total and final confirmation. No extra review screen. Suggested command: $impeccable layout.

### [P2] Selected filter loses contrast in some states

Live review observed near-white selected text on a pale background. InventoryHome aria-pressed state relies on inherited CSS; new generic hover rules can conflict with old selected styling.

Fix: explicit selected/hover text/background/border colors, e.g. primary blue/white or graphite on neutral fill, with state verification. Suggested command: $impeccable harden.

## Cognitive load and emotional journey

Three failed checklist areas: one obvious route per task, progressive disclosure of rare work, and one primary action per stage. This is moderate extraneous cognitive load. Sale selection is duplicated; edit save competes with review. Three availability filters are a manageable choice count; the issue is consistency, not their number. Variant editing exposes six identity/price/stock fields plus activation/photo; nine optional document fields can be disclosed later.

Stock recognition begins confidently. Selection loses momentum across list → modal → editor; editing loses confidence at a numbered creation process. Clear final consequences are reassuring and should be preserved while middle steps are removed.
