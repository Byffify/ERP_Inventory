71 domain tests + 27 browser scenarios ผ่าน; TypeScript/buildผ่าน; รูป/PDF/PNGตรวจจริง ไม่ยืนยันการใช้กับร้านหรือมือถือจริง

ให้เนเน่ตรวจหลักฐาน E01–E08; เซฟตรวจ workflow ลดสต๊อกหลังเขียนบิลมือกับ workflow ออกบิลและทดสอบผู้ใช้; โอ๊ตรับภาพ stock cards/บิลล่าสุดและสถานะทดสอบ

ส่วนด้านล่างเป็นประวัติรอบแรก บางชื่อไฟล์และ UX ถูกแทนที่ตาม S4-ui-update.md


## ความสามารถและสถานะ
**ทำงานจริงในเดโม:** ค้นสินค้า ดูยอด รับเข้า บันทึกร่าง ตรวจบิล ยืนยัน แก้โดยปรับผลต่าง ยกเลิกแล้วคืนยอดล่าสุด ประวัติรุ่น โหลด localStorage รีเซ็ตแบบยืนยัน และดาวน์โหลดภาพบิล PNG ภาษาไทย
**ภาพประกอบ:** S4-main-screen.png เป็นภาพจากเดโมจริง S4-slide.png เป็น layout สไลด์จากภาพดังกล่าว ไม่ใช่หลักฐานการใช้ในร้าน
**ยังไม่ทำ:** production, auth, backup/recovery, multi-user/multi-device, LINE integration, บัญชี เครดิต ภาษี AI จัดซื้ออัตโนมัติ และชำระเงินออนไลน์

## เนเน่รับ
Evidence Log รอเจ้าของหลักฐานตรวจ E01–E08 และเติมวัน ผู้ให้ข้อมูล บทบาท จำนวนร้าน/คน คำถาม และตัวอย่างบิล/สินค้า/หน่วย ไม่ใช้วันทำงานแทนวันสัมภาษณ์

## เซฟรับ
Scope เดโมและจุดยืนยันตามสเปก ตรวจสอบกับร้านก่อน pilot
ข้อสังเกตจากการตรวจภายใน: flow ทำร่าง ยืนยัน แก้ ยกเลิก และรับเข้าทำงานตาม checklist; ขนาด320px ไม่ล้นหน้าในกรณีที่ตรวจ; error ไม่เปลี่ยนชื่อช่องกรอกและมีคำแนะนำแก้
สิ่งเหล่านี้เป็นผลตรวจระบบโดยผู้พัฒนา ไม่ใช่ผลทดสอบความสะดวกของร้านหรือผู้ใช้40+ ยังไม่มี usability results

### ก่อน pilot
1. ยืนยันผู้ใช้งาน อุปกรณ์ ผู้ตัดสินใจซื้อ และผู้จ่าย
2. ตรวจ SKU สี/ไซซ์ หน่วยและอัตราแปลงที่ร้านใช้จริง ก่อนเปลี่ยนโมเดลข้อมูล
3. ตรวจนับยอดตั้งต้นและตกลงจุดยืนยันขาย แก้ ยกเลิก และรับเข้า
4. กำหนด backup/recovery ความเป็นส่วนตัว และสิทธิ์; หากใช้หลายเครื่องต้องออกแบบ backend/transaction ใหม่
5. ทดสอบมือถือจริง และการใช้งานกับร้าน วัด baseline/task completion/errors/time โดยไม่อ้างผลล่วงหน้า
6. ประเมินต้นทุนตั้งข้อมูล ฝึกใช้ support และ hosting ตามขอบเขต pilot แยกจากเดโม

ชื่อโปรเจกต์ยังเป็นชื่อชั่วคราว ไม่รับรองการเป็นใบกำกับภาษี และภาพ Note/บิลที่ส่งไปแล้วไม่อัปเดตอัตโนมัติ
