# S4 — สเปกที่อนุมัติ
**ฉบับปัจจุบัน:** อ่าน S4-catalog-spec.md และ S4-ui-update.md ร่วมด้วย ขอบเขตได้รับการขยายให้เพิ่มรูป/รุ่น/SKU, สต๊อกแบบการ์ดและลดจำนวนเอง, ขายหน้าเดียวไม่มีบันทึกร่าง, ปุ่มออกบิลในสรุปและบิลเงินสดขาว–ดำตาม reference รวม PNG/พิมพ์/PDF ข้อความกำกับจำลองถูกนำออกจาก UI ตามคำขอล่าสุด ส่วนด้านล่างเป็นสเปกรอบแรกเพื่อเก็บประวัติ

ชื่อชั่วคราว: ระบบสต๊อกและบิลร้านขายส่งชุดชั้นใน

เดโมข้อมูลจำลอง เบราว์เซอร์เครื่องเดียว ไม่มี login/backend/LINE API ออกแบบ mobile first เริ่ม 320px ตาม DESIGN.md ทุกหน้ามีคำว่า “โหมดสาธิต — ข้อมูลและราคาจำลอง”

สินค้า → ทำบิลร่าง → ตรวจรายการ → ยืนยันขาย → บิลและยอดหลังขาย; รับเข้า แก้ และยกเลิกได้
ร่างไม่ตัด ไม่จอง; ยืนยันบันทึกทั้งบิลหรือไม่บันทึกเลย; ยืนยันซ้ำไม่ตัดซ้ำ; แก้ใช้ยอดปัจจุบัน + ขายเดิม − ขายใหม่; ยกเลิกคืนฉบับล่าสุดครั้งเดียว; รับเข้าซ้ำไม่เพิ่มซ้ำ หนึ่ง SKU หนึ่งหน่วย ไม่แปลงแพ็กเป็นชิ้น

React/TypeScript/Vite + localStorage snapshot เดียว เงินจำนวนเต็มสตางค์ ตรวจครบก่อนบันทึกและแสดงสำเร็จ เก็บ history บิลและ stock movements บิล PNG มีรหัส/รุ่น/วันเวลา/จำนวน/หน่วย/ราคา/ยอดรวมและข้อกำกับจำลอง

ข้อมูลจำลอง: A ดำ M 12 แพ็ก @180 บาท; B ไม่แยกสี/ไซซ์ 20 ชิ้น @60 บาท; C ครีม L 0 แพ็ก @200 บาท
ตัวอย่าง 12−3=9 แพ็ก; 3×180=540 บาท ไม่ใช่ราคาหรือข้อมูลจริง

ตรวจ: รับเข้า ร่าง ยืนยันซ้ำ แก้เพิ่มลด เปลี่ยน SKU ยกเลิกซ้ำ ของไม่พอทั้งบิล จำนวนและเงินไม่ถูกต้อง บันทึกล้มเหลว โหลด/รีเซ็ต PNG ภาษาไทยและ mobile widths 320/360/390/768/1280px รวม landscape/ข้อความยาว/ขยายข้อความ

ไม่รวมบัญชี เครดิต ภาษี marketplace AI การจัดซื้ออัตโนมัติออนไลน์ ระบบหลายผู้ใช้ หรือการซิงก์ร้านจริง
ก่อน pilot ยืนยันผู้ใช้งาน อุปกรณ์ หน่วยสินค้า กระบวนการร้าน ยอดตั้งต้น เพิ่ม backup/recovery และสิทธิ์/หลายเครื่องตามความจำเป็น พร้อมประเมินต้นทุนใหม่
